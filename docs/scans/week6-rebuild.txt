## Found and fixed
1. `make down` failed while the build VM was shut off (the normal state with
   one VM at a time): the root output ssh_command put a null IP into a string.
   Nothing was destroyed. Fixed in platform-lab 5c1bef5 (null output when off).
2. The unsigned-image test package is built by hand in the runbook; built
   through airgap-packages.sh its file-name check looks for the directory name
   (unsigned-image), not the package name (admission-test-unsigned). The
   package was built and signed; its signature was verified (zarf package
   inspect --key: Verified OK) and SHA256SUMS regenerated by hand.
3. Argo CD deploys before the images are published, so Kyverno logged 145
   PolicyViolation "evaluation error" events (18:31-18:43) while the fresh
   registry was empty; the agent reported its own CronJob from them. They
   expire within an hour; deleted with the user's OK to save the wait. Build
   guide: wait for them before evaluating.
4. The verify script's egress check printed nothing (the rebuilt VM has new
   SSH host keys; the old key in ~/.ssh/known_hosts refused it). Rechecked with
   the host key Ansible recorded: blocked. `make airgap-disconnect` itself
   checks egress too.
5. The unsigned-image test leaves its own PolicyViolation event; run before
   the eval, it is a finding in every run. Deleted with the user's OK.
6. KEDA's KEDAScaleTargetDeactivationFailed at the airgap VM's boot (API server
   not ready), followed by successful deactivations, was an ambient finding in
   4 of 4 runs (first pass kept: week6-rebuild-airgap-status-eval/first-pass/).
   Deleted with the user's OK; fixed in dba61ba (the pair is in RESOLVED_BY).
7. On the freshly booted airgap VM many system pods had restarted once at boot
   (now Running and Ready); the 4B model reported those past restarts as crash
   loops in every control (one report ran past max_tokens and ended unknown),
   and a CronJob Job still running as a crash loop (i2). Fixed in 7229ac8 (the
   user chose to fix before v1.0): a ready pod whose containers have run 10+
   min says "earlier; running 10+ min, ready now: not a fault"; a completed
   pod's earlier error likewise; a running Job with healthy pods and no
   failures is not a fault. Checked live (f05's OOM loop stays a fault) and
   offline (a crash-looping and a failed Job stay faults). After every VM boot
   the eval now waits until no restarted container has run under 10 minutes.
8. Fresh-cluster slowdown: model time per turn was 7-12 s for the first ~15
   minutes on the rebuilt build cluster (Week 6: 5-10 s) with the same number
   of turns, back to normal after about 20 minutes (CPU-only model sharing the
   node with the platform's first-start work). Not a regression.
9. Cosmetic, not changed: platform-lab's Makefile default `NAME ?= stig-scan`
   is passed to every `make image`; publish-image.sh ignores it for upstream
   references.
